# خطة إكمال التعميم والتطوير — PRB-NAZRA-002 (C2–C8 + بقية C5)

الهدف: تعميم التحسينات التي بُنيت على الفواتير إلى بقية الشاشات، وإغلاق الأجزاء المتبقية من كل دفعة، بخطوات صغيرة لكل منها فحص قبول مستقل.

## المرحلة ١ — توحيد عرض المبالغ (C2)
1. استبدال المنسقات القديمة بمكون المبلغ الموحد في جداول: العملاء، الموردين، المشتريات، السندات، المصروفات، الخزائن، الأصناف، الشيكات.
2. بطاقات الملخص في كل الشاشات تحترم زر إخفاء الأرصدة.
3. تحويل ملفات PDF من الريال إلى الجنيه المصري.
- قبول: لا يتبقى أي منسق قديم (فحص آلي يمنع عودته)، والاختبارات الحالية تنجح.

## المرحلة ٢ — الجداول (C3)
1. مكون جدول موحد مستخرج من شاشة الفواتير: كثافة، إظهار/ترتيب الأعمدة، رأس مثبت، Chips بعدادات، عداد الفلاتر مع زر الإلغاء.
2. تثبيت العمود الأول يمينًا وعمود الإجراءات يسارًا.
3. "تحميل المزيد" بدل الصفحات مع حفظ مكان التمرير.
4. التطبيق تدريجيًا: العملاء ← الموردون ← المشتريات ← السندات ← الأصناف ← المصروفات.
- قبول لكل شاشة: لا تمرير أفقي للصفحة عند 360/768/1280، الفلاتر تصل للخادم، لقطة شاشة.
- لا virtualization إلا بعد قياس يثبت الحاجة.

## المرحلة ٣ — نماذج المستندات (C4)
1. تطبيق Ctrl+S/Esc، حماية المغادرة، القفز لأول خطأ، استعادة المسودة، شريط الإجماليات، زر حفظ بمؤشر تحميل على: فاتورة المشتريات، عرض السعر، أمر البيع، سندات القبض والصرف، المرتجعات، القيد اليومي.
2. بطاقة العميل السريعة (الرصيد، الائتمان المتبقي، الهاتف) بجوار اسم العميل.
3. اختبارات وحدة للخطافات المشتركة + تجربة حفظ فعلية لفاتورة.

## المرحلة ٤ — بقية السلامة المالية (C5، بموافقتك المسجلة)
1. إلغاء السند المرحّل بقيد عكسي بتاريخ السند الأصلي، مع رفضه إن كانت الفترة مقفلة حتى اعتماد فتحها، وتحديث الكشوف والإحصاءات.
2. طلب موافقة لتجاوز سقف خصم البائع.
3. طلب موافقة لتجاوز سالب الخزينة.
4. حساب مخصص لفروق التقريب وقيده الآلي.
5. تحذير برتقالي وتأكيد عند البيع أقل من التكلفة.
- كل بند: عملية ذرية في قاعدة البيانات معزولة حسب الشركة، منع التكرار، اختبارات، وتجربة حية على بيانات اختبار تُزال بعدها. لا حذف نهائي.

## المرحلة ٥ — الطباعة والتصدير (C6)
1. تمرير الرصيد السابق/النهائي واسم المستخدم من شاشة الطباعة الفعلية.
2. معاينة قبل PDF في كل المستندات، وإخفاء الشارات.
3. Excel بترويسة الشركة (الشعار، الاسم، عنوان التقرير، التاريخ).

## المرحلة ٦ — التنقل والتقارير (C7)
1. فترات سريعة بالتقارير (اليوم، الشهر، الربع، السنة).
2. بحث دليل الحسابات بتوسيع الشجرة وتمييز النتيجة.
3. ربط مركز الإشعارات بالتبويبات.

## المرحلة ٧ — الموبايل (C8)
1. بطاقة جدول مدمجة قابلة للتوسيع، تُستخدم تلقائيًا تحت عرض التابلت في كل الجداول المعممة.
2. شريط إجراءات سفلي للنماذج، والنوافذ الجانبية كورقة سفلية.
3. أهداف لمس 44px، وفحص لقطات عند 393px.

## المرحلة ٨ — التحقق النهائي
- تشغيل كل الاختبارات، فحص RTL، لقطات لكل شاشة معممة، وتحديث قائمة المهام وسجلات الأدلة.

## خارج النطاق / ينتظرك
- القرارات ٣٦١–٣٦٣.
- اختبار استعادة النسخة الاحتياطية (التنزيل ليس اختبار استعادة).

## تفاصيل تقنية
- الالتزام بالطبقات الأربع: الواجهة لا تلمس قاعدة البيانات؛ الاستعلامات عبر hooks ومستودعات.
- مكونات مشتركة جديدة: `DataTableShell`، `PinnedColumns`، `LoadMoreFooter`، `MobileExpandableCard`، `DocumentFormShell`، `CustomerQuickCard`، `exportExcelWithHeader`.
- RPCs: `reverse_posted_voucher`، `request/resolve_discount_override`، `request/resolve_cash_negative_override`، `post_rounding_difference` — كلها `SECURITY DEFINER` مع تحقق tenant ومنع إعادة استخدام الموافقة.
- لا اعتماديات تشغيل جديدة؛ اختبارات vitest بجانب الموجودة، وPlaywright للقطات.
- التنفيذ بالترتيب ١→٨، مع تحديث roadmap بعد كل مرحلة.
