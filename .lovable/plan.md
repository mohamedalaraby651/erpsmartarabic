# خطة تطوير صفحة الفواتير — OPA-INV-UX-001

الحالة: Candidate Batch (مقترح للمراجعة، غير مُصرّح بالتنفيذ بعد)
النطاق: شاشة الفواتير فقط `/invoices`. لا تعميم على شاشات أخرى قبل قبول OPA-UI-003.
خارج النطاق: أي migrations أو RLS أو تعديل منطق الترحيل المحاسبي أو الدفعات أو F2.

## المشكلات الملحوظة اليوم
1. الصفحة طويلة: رأس + بطاقات ملخص + شريط تحديد جمعي + شريط أدوات + جدول = تمرير كبير قبل رؤية أول صف.
2. شريط التحديد الجمعي ظاهر دائمًا حتى عند عدم وجود تحديد، فيستهلك مساحة بلا فائدة.
3. لا توجد اختصارات لوحة مفاتيح ولا وصول سريع لأكثر الإجراءات تكرارًا (تسجيل دفعة، طباعة، بحث).
4. البحث يتطلب الكتابة ثم الانتظار؛ لا يوجد تمييز للنص المطابق ولا مسح سريع.
5. لا يوجد ترقيم/تحميل تدريجي واضح ولا مؤشر هيكلي (skeleton) متسق أثناء التحميل.
6. الصفوف لا تدعم فتح تفاصيل سريع بدون مغادرة الصفحة.

## المراحل

### المرحلة 1 — تقليص الضجيج البصري (أثر كبير/مخاطرة منخفضة)
- إخفاء شريط التحديد الجمعي حتى أول تحديد، وإظهاره كشريط عائم أسفل الشاشة عند التحديد.
- دمج بطاقات الملخص في شريط مضغوط قابل للطي، مع تذكّر حالة الطي لكل مستخدم.
- توحيد المسافات والارتفاعات حسب الكثافة المختارة (مريح/متوسط/مضغوط).

### المرحلة 2 — سرعة الاستخدام
- اختصارات لوحة مفاتيح: `/` للبحث، `n` فاتورة جديدة، `e` تصدير، `Esc` إلغاء التحديد، أسهم للتنقل بين الصفوف.
- إظهار دليل الاختصارات عبر `?`.
- تمييز النص المطابق داخل نتائج البحث وزر مسح فوري.
- إبقاء رأس الجدول ثابتًا أثناء التمرير وشريط الأدوات لاصقًا.

### المرحلة 3 — لوحة تفاصيل جانبية
- النقر على الصف يفتح لوحة جانبية: بيانات الفاتورة، البنود، الدفعات، سجل الاعتماد.
- إجراءات داخل اللوحة: تسجيل دفعة، طباعة، فتح الصفحة الكاملة.
- قراءة فقط لأي بيانات مالية؛ الكتابة تمر عبر المسارات القائمة فقط.

### المرحلة 4 — أداء ملموس
- قياس أولًا: زمن أول رسم للجدول وزمن الاستجابة للفلترة.
- تحميل تدريجي/افتراضي للصفوف عند تجاوز حد معيّن.
- تقليل إعادة الرسم عند تغيير الفلاتر، وتثبيت هيكل تحميل موحّد.

### المرحلة 5 — موبايل وRTL
- عرض الصفوف كبطاقات على الشاشات الصغيرة مع أولوية: الرقم، العميل، المتبقي، الحالة.
- أهداف لمس 44px، ومراجعة اتجاه العناصر في RTL.

### المرحلة 6 — دليل التنفيذ
- لكل مرحلة: Precondition → Action → Expected State → Evidence → Recovery.
- توثيق النتائج في سجل تنفيذ مستقل، والقبول قرار بشري.

## تفاصيل تقنية
- الطبقة: عرض وتفاعل فقط (`InvoicesPage.tsx`، مكوّنات الجدول المشتركة، `useTableLayout`).
- حالة الطي والاختصارات تُحفظ ضمن مفتاح التفضيلات الحالي `table-layout:v2:<userId>:<section>` دون كسر الترحيل.
- لا تغيير في `useInvoicesList` عدا ما تتطلبه القياسات، ولا تعديل على عقود البيانات.
- كل مرحلة تنتهي بفحص أنواع + فحص حي على 360/768/1280.
