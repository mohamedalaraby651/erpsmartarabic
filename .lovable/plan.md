## 0. تصحيح الوضع الحالي (G-RETRO)

نُفِّذت في الدور السابق أجزاء من M1 وM2 وM3 قبل وجود تفويض. لذلك:

- تُعاد تصنيفها: `EARLY EXECUTION — UNGATED`، وليست مقبولة.
- لا تُبنى عليها أي مرحلة جديدة قبل مراجعتها.
- الخيارات المعروضة عليك لكل مرحلة: **قبول بأثر رجعي** أو **تعديل** أو **تراجع (revert)**.
- ما نُفِّذ فعليًا:
  - M1: شريط التحديد الجمعي يظهر عند التحديد فقط، ملخص مالي قابل للطي مع حفظ الحالة، تقليل ارتفاع البطاقات.
  - M2: شريط الأدوات لاصق، زر مسح البحث، اختصارات `/ N R Esc ?` مع دليل. **لا يوجد** highlight ولا تنقّل بالأسهم.
  - M3: لوحة نظرة سريعة تقرأ بيانات الصف فقط، وتفوّض الدفع والطباعة والفتح الكامل للمسارات القائمة. **لا** بنود ولا سجل اعتماد ولا دفعات.
- فجوات حوكمية قائمة في المنفَّذ وتُعالج ضمن الـGates:
  - حفظ طي الملخص يستخدم مفتاحًا مستقلًا `invoices:summary-strip` بدل مفتاح التفضيلات المعتمد.
  - الاختصارات تحمي حقول الكتابة وcontenteditable فقط — لا تغطي الحوارات وقوائم popover وselect وcombobox.
  - نقر الصف يفتح اللوحة دون عقد استثناء صريح للعناصر التفاعلية داخل الصف (يعتمد حاليًا على stopPropagation موضعي).
  - لا يوجد Evidence Pack بصيغة Regression Boundary.

## M1 — تقليص الضجيج البصري

الحالة: EARLY EXECUTION — يحتاج Gate.

خطوات:
1. نقل تفضيل طي الملخص إلى مفتاح التفضيلات المعتمد `table-layout:v2:<userId>:invoices` بقسم presentation فقط (density، summary collapsed، columns، widths، order، visibility).
2. تثبيت Invariant لشريط الإجراءات الجمعية: لا يحجب أبدًا محتوى قابلًا للتفاعل ولا الصف النشط؛ التخطيط يعوّض المساحة التي يشغلها.
3. إثبات الـInvariant عند 360 و768 و1280: آخر صف، الترقيم، أزرار الإجراءات كلها قابلة للوصول أثناء ظهور الشريط.
4. Evidence Pack + Gate M1.

## M2 — Keyboard + Search + Sticky Workspace

الحالة: EARLY EXECUTION جزئي — يحتاج Keyboard Guard Contract قبل الاعتماد.

Keyboard Ownership Contract:
- الاختصارات تعمل فقط عندما تملك مساحة العمل ملكية لوحة المفاتيح.
- تُعطَّل داخل: input، textarea، select، combobox، date picker، dialog، popover/menu، contenteditable، وأي عنصر تحرير.
- `Esc` يغلق أعلى واجهة مؤقتة أولوية أولًا، ثم يلغي التحديد.

خطوات:
1. توسيع الحارس ليكتشف الحوارات والقوائم المنبثقة (`[role=dialog]`، `[data-state=open]` لعناصر popover/menu/combobox) ويصمت داخلها.
2. توثيق قرار `e` للتصدير: إما تفويض صريح لزر التصدير القائم أو حذف الاختصار — لا تنفيذ تصدير مستقل.
3. تنقّل الأسهم: قرار معماري صريح — roving tabindex ينقل focus فعليًا إلى الصف، مع `aria-selected`/active row، ودون كسر سلوك الجدول الأصلي. إن تعذّر دون كسر، يُسقط الاختصار ويُوثّق.
4. Search Contract: الإبقاء على debounce الحالي ودلالات البحث كما هي؛ زر المسح لا يفقد الفلاتر ولا الترتيب ولا الأعمدة ولا التحديد؛ التظليل عرض بصري فقط بنصوص آمنة دون HTML غير موثوق؛ يعمل مع العربية وRTL. Highlight ≠ query change.
5. Runtime Proof: كتابة `n` داخل حقل بحث وحقل حوار لا تفتح فاتورة؛ `Esc` داخل حوار يغلق الحوار فقط.
6. Evidence Pack + Gate M2.

## M3 — Invoice Details Drawer

الحالة: EARLY EXECUTION مبسّط — يحتاج Gate مستقل قبل أي توسعة.

عقد اللوحة:
- إسقاط قراءة فقط لسجل الفاتورة القائم.
- لا مصدر حقيقة مالي جديد، ولا منطق دفع أو اعتماد مكرر، ولا استدعاء مباشر لقاعدة البيانات من الواجهة.
- تسجيل الدفعة تفويض إلى مسار الدفع القائم. الطباعة والاعتماد يعرضان المصدر القائم فقط.

خطوات:
1. تثبيت عقد نقر الصف: يفتح اللوحة فقط عندما لا يكون الهدف عنصرًا تفاعليًا داخل الصف (checkbox، رابط، زر، قائمة).
2. قرار التوسعة: هل تُعرض البنود والدفعات وسجل الاعتماد؟ إن نعم، تُقرأ عبر طبقة القراءة القائمة فقط، وبدون استعلام جديد من الواجهة — وإلا تبقى اللوحة على بيانات الصف.
3. Runtime Proof: النقر على checkbox أو زر إجراء أو رابط لا يفتح اللوحة.
4. Regression Proof: لا سجلات دفع أو قيود جديدة نتيجة فتح اللوحة.
5. Evidence Pack + Gate M3.

ممنوع بلا تفويض جديد: تغيير API/query contract، الفلترة على الخادم، دلالات الترقيم، Query Service جديد، تعديل repository، تغيير مصدر الحقيقة.

عقد: نفس السجل، نفس الإجراءات، نفس الحالة، نفس دلالات الفلترة، نفس الصلاحيات — اختلاف في العرض فقط.
