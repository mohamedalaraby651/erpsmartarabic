## 2. Remediation rule applied

One uniform authority rule, mirroring ADR-0045 D-1:

```
acting tenant := public.get_current_tenant()      -- server-derived from auth.uid()
caller-supplied tenant/user argument
        └── may only AGREE with it, never widen it
```

- Mismatch ⇒ `RAISE EXCEPTION 'cross-tenant access denied' USING ERRCODE = '42501'`.
- `auth.uid() IS NULL` (service_role, triggers, internal definer chains) keeps the
  previous behaviour, so RLS policies (`get_user_tenant_id(auth.uid())`,
  `get_user_tenants(auth.uid())`), posting functions calling `is_period_closed`,
  and the `render-pdf` / `validate-invoice` edge functions are unaffected.
- `find_duplicate_customers` no longer performs a global scan when the argument is
  `NULL`; it resolves the tenant server-side and returns nothing without context.
- Grant surface tightened explicitly: `REVOKE … FROM PUBLIC, anon` and
  `GRANT EXECUTE … TO authenticated, service_role` on all seven.
